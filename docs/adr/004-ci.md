# ADR-004: Continuous integration

- Status: Accepted
- Date: 2026-10-30

## Decisions

- One workflow, three jobs: `backend` (ruff, ruff format, mypy, pytest on Python 3.12), `frontend` (eslint,
  vitest, `tsc` + build on Node 22) and `docker` (build images, `compose up --wait`, smoke test). The Docker
  job runs only if the first two pass, which saves minutes.
- The CI never calls the real LLM and holds no secrets. Tier evals are a separate manual workflow that uploads
  its reports as an artifact for Vân to judge (CLAUDE.md: they must not block CI).
- `scripts/compose-smoke.sh` is the single smoke test, used by CI and runnable locally. It checks the web page,
  `/api/health`, `/api/support`, and that a Tier 3 message is answered by the server-side script with
  `pinnable: false` and a 115 contact. For a normal message it accepts a real LLM answer or a clean
  `llm_not_configured` 503, so it works with and without a key.
- Actions are pinned to major versions (`@v4`, `@v5`). Dependabot and hash pinning are left for later.

## Verified how

The workflows could not be run on GitHub from this machine (the local folder is not a git repository yet).
The same commands were run in clean `python:3.12-slim` and `node:22-slim` containers, and the `docker` job was
simulated from a clean copy of the repo with `.env` created from `.env.example`.

## Known gaps

- Web fonts come from Google Fonts at runtime (the visitor's IP reaches Google). Self-hosting is a privacy
  improvement for a health app and should be decided before the beta.
- No image scanning, no dependency audit and no branch protection yet.
